# AgriYield AI 🌾
### Machine Learning-Based Crop Yield Prediction and Agricultural Data Analytics

AgriYield AI is an educational, end-to-end supervised machine-learning project for estimating historical crop yield from Indian state-level agricultural data. It includes data preparation, exploratory analytics, model comparison, a Streamlit dashboard, tests, and reproducible training scripts.

> **Important:** This is an academic decision-support prototype, not a production agricultural advisory service. Predictions reflect patterns in historical data and should not be treated as guaranteed future yields.

## Dataset

The project uses `crop_yield_in_indian_states.csv` from the public repository [`jainvandan7/crop-yield-ml`](https://github.com/jainvandan7/crop-yield-ml). The repository describes 19,689 observations from 1997–2020 and these columns: `Crop`, `Crop_Year`, `Season`, `State`, `Area`, `Production`, `Annual_Rainfall`, `Fertilizer`, `Pesticide`, and `Yield`.

The dataset is downloaded automatically by `src/data_loader.py` if it is not already in `data/raw/`.

**Target:** `Yield`  
**Predictors used:** `Crop`, `Crop_Year`, `Season`, `State`, `Annual_Rainfall`, `Fertilizer`, `Pesticide`  
**Excluded:** `Production` and `Area`. Since `Yield = Production / Area` in this dataset, using those columns as predictors would leak information about the target.

Dataset source and context:
- Dataset/code repository: https://github.com/jainvandan7/crop-yield-ml
- Dataset file: https://github.com/jainvandan7/crop-yield-ml/blob/main/crop_yield_in_indian_states.csv

Please verify the source's current terms and cite the original dataset repository in your submitted report. The dataset is not bundled in this starter package; it is fetched from the public source when needed. Downloads are schema-validated before being cached locally to avoid storing an invalid response as the dataset.

## Features

- Data-quality summary and exploratory visualizations.
- Leakage-aware preprocessing pipeline.
- Four regression models: Linear Regression, Decision Tree, Random Forest, and Gradient Boosting.
- Consistent train/test evaluation using MAE, RMSE, and R².
- Saved model pipeline and model-comparison CSV.
- Interactive Streamlit dashboard for data exploration and predictions.
- Automated unit tests.

## Setup (Windows PowerShell / VS Code)

Use Python 3.11 or 3.12.

```powershell
cd AgriYield_AI
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, run this in the current terminal:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

## Train and evaluate

```powershell
python train_models.py
```

The script downloads the dataset if needed, cleans invalid rows, trains and compares models, prints metrics, and saves:
- `models/best_model.joblib`
- `reports/model_comparison.csv`
- `reports/test_predictions.csv`
- `reports/feature_importance.csv` (when supported)

Metrics are generated by your local run; do not copy placeholder or online scores into your report. The default evaluation protocol is a temporal holdout using the latest three observed years, so results may differ from earlier random-split runs.

## Run the dashboard

```powershell
streamlit run app.py
```

Open the local URL printed by Streamlit, usually `http://localhost:8501`. Train the models first so prediction and model-comparison sections have saved artifacts.

## Run tests

```powershell
python -m pytest -q
```

Tests use small local fixtures and do not require downloading the full dataset.

## Methodology notes

1. The target is a continuous numeric yield value, so this is a **regression** task.
2. The project drops `Area` and `Production` to prevent direct target leakage.
3. Categorical columns are imputed and one-hot encoded; numeric predictors are median-imputed.
4. Model comparison uses a chronological holdout by default: the latest three observed years are held out for testing and earlier years are used for training. This better approximates predicting later years than a random row split. Rows without a valid year are excluded from that holdout evaluation. The selected model is then refitted on all labelled rows for the demo app. Pass `split_strategy="random"` to `train_and_compare` only when you explicitly want to reproduce a random-split experiment.
5. MAE and RMSE are in the dataset's yield units. R² is unitless and can be negative on held-out data.
6. Feature importance is associative, not causal.

## Limitations and future scope

- Dataset values and definitions depend on the source and historical reporting.
- The features do not include every local condition affecting yield, such as soil properties, irrigation, pests, or within-season weather.
- Historical association does not guarantee future predictive performance, and temporal holdout results can still be affected by shifts between years.
- Future work could use temporal validation, region-specific evaluation, external soil/weather datasets, uncertainty estimates, and farmer/subject-matter-expert validation.
